    What's an ERD

    An entity relationship diagram is a map of a database. Each box is a table, and each line shows how two tables connect.

    Before writing any SQL against a database you haven't seen, look at its ERD. It tells you which tables exist, what columns they hold, and which columns you can use to join them together.

    The diagram on the right is the database you'll build in the Creating tables lesson: a Customers table and an Orders table, linked by customer_id.

    The four parts

    Entity

    A table, drawn as a box with its name in the header. Customers and Orders are entities.

    Attribute

    A column, listed inside the box with its data type on the right, such as customer_name TEXT.

    Primary key PK

    The column that uniquely identifies each row. No two customers can share a customer_id, and it can't be empty.

    Foreign key FK

    A column that holds another table's primary key. Orders.customer_id points at the customer who placed the order.

    Reading the lines

    Each end of a relationship line carries a symbol, called crow's foot notation. The symbol next to a table says how many rows of that table can match one row at the other end.

    Read the example in both directions. Starting from Customers: one customer has zero or many orders, because a new customer may not have ordered yet. Starting from Orders: each order belongs to zero or one customer. It's "zero or one" because Orders.customer_id allows NULL. If that column were NOT NULL, the circle would become a second bar, meaning every order must have exactly one customer.

    Three kinds of relationship

    One to many

    The most common. One customer, many orders. The foreign key always lives on the "many" side, in Orders.

    One to one

    Each row matches at most one row in the other table, for example a user and their profile settings. Often merged into one table.

    Many to many

    An order holds many products, and a product appears on many orders. You can't link them directly, so a junction table sits in between. You'll build one in the Normalisation lesson, and meet another in Northwind later on.
